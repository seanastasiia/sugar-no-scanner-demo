# Bugs

This file tracks open limitations and only recent resolved regressions. Older history remains recoverable in Git.

## Open

- **2026-09-04, preview: shared internet cards need isolated-database activation for Personal Fit.** Whole-composition verification and an additive migration are tested locally, but the new flag is off. An approved test Supabase target and source-permission acceptance are prerequisites; no production database was changed.
- **2026-09-04, OFF source completeness remains limited.** The import accepted 596 new GTINs from 15,669 regional rows. Missing brand, package dimension or core nutrients remain rejection reasons. CSV has no reliable ingredient-language labels; exact follow-ups added 62 assessments across original/new OFF records, but unknown composition is never guessed. The original 500-record layer is unchanged.

- **Personal Shelf coverage is still not catalog-wide.** A reproducible offline audit accounts for all 20,120 source records, but the preview can currently assess 3,712 rows across 19 categories. Another 3,605 rows belong to supported types but still lack sufficient exact evidence; 12,803 rows are outside the model. The audit found 275 conservative multilingual review candidates, no usable cross-source GTIN group, and 2,199 supplied identifiers that fail supported GTIN length/checksum validation. None are silently merged or used as barcodes. Other products still need source/variant review; a wrong detected pack must not be silently corrected. Dense photos keep the existing ten-product limit, so not every visible box is retained.
- **Shared internet-card coverage is conservative.** The new page-checked lane accepts reviewed retailer hosts and explicit supported nutrition formats, not arbitrary AI answers. Translation without a source-confirmed exact identity, an unsupported page, an invalid/truncated GTIN or a source conflict can still leave a product or nutrient unknown. Old web-cache entries are not silently upgraded into verified cards; existing source layers are not globally deduplicated.

- **The composition batch contains 34 contradictory source tables.** This includes the two previously quarantined Livinn products plus Barbora, Rimi and Livinn anomalies. New-category guards also reject literal zero sugar/salt/saturates when the same exact page contradicts that zero through its ingredients or total fat. A page without enough consistency fields can still contain an undetected source error, so surprising scores need package review. Rejected observations remain identifiable but unrated; the validator lists the exact IDs.

- **Local production-mode Mobile Safari tests lack an HTTPS harness.** With `E2E_PRODUCTION=1`, production correctly marks the session cookie Secure, but local `http://127.0.0.1:3000` requests omit it and protected APIs return 401. The normal development-server suite is the supported local acceptance command; the built deployment must also be smoke-tested over Railway HTTPS. Do not weaken production cookie security to make this optional local mode pass.
- **Long local Mobile Safari runs can stall before a test starts.** On `eaa7f73`, two uninterrupted 58-case runs each timed out in the feedback test's initial `page.goto`, before its assertions. That case passed alone and after its predecessor; all 58 cases passed in two fresh 29-case shards with one worker and no retries. The root cause is not proven. No assertions or cookie protections were weakened; see [cereal preview QA](docs/test-runs/2026-09-03-cereal-shelf-preview.md).
- **Personal Shelf Rank remains an unvalidated, opt-in preference model.** The expanded batch is not a conversion of all 19k source records or a unique-product census. Unknown ingredient wording, essential missing data and contradictory tables remain unscored. Candy is heavily concentrated in Low fit, sauces and ice cream have low assessable coverage, and many bread ranges cross a fit band because fiber is unknown. These are calibration warnings, not hidden normalization. Store category mistakes remain possible; real-package and category-order review is required before replacing default Fit.
- **Batch coverage is partial when sources rate-limit.** Barbora and Open Food Facts returned HTTP 429 during this run; each source queue was stopped. Missing URLs are checkpointed, not silently filled or retried continuously. Some expired URLs return 404 or redirect to a different SKU and are rejected. Explicit later resumption must respect source cooldowns; no scheduler was created.
- **The isolated preview has process-only online cache.** It deliberately has no Supabase or Amplitude credentials, protecting existing production/staging data. Restarting the preview loses its online cache, not its checked-in catalog/evidence; repeated lookups can cost provider requests again. Durable preview storage requires a separately approved Supabase target.

- **Pilot reporting needs test-traffic exclusion.** Production events use a separate Amplitude project. Demo scans and synthetic QA sessions are not real recognition accuracy or shopper conversion evidence. Filter demo sources and recorded QA sessions before interpreting launch metrics.

- **Feedback email is best-effort.** Production and staging notifications retry one transient failure, but do not have a durable delivery queue. A process restart or exhausted Resend quota can prevent the email; feedback remains in Supabase and metadata-only delivery logs identify failures.

- **Normal-mode contrast follows the approved Pen design.** White text on the colorful fit gradients and the original system-blue controls does not meet every AA text contrast threshold. Increased-contrast mode provides darker text/actions and is checked separately.
- **Rounded typography is platform-dependent on the web.** Apple Safari resolves the system rounded face; browsers without it use a system fallback. Apple font binaries are not included in the repository.
- **Historical catalog snapshots do not yet contain carbohydrates.** The app now supports exact source-backed carbohydrates per 100 g or 100 ml, but existing checked-in rows omit the field until their next retailer, Open Food Facts or grounded-source refresh. Sugar.no fit remains available from protein and total sugar and is not recalculated.
- **Latvia coverage is not universal.** Private labels, unreadable variants and products without an exact cited per-100 table can remain unresolved. They must not receive a guessed fit.
- **Physical-store accuracy is not validated.** Packaging glare, low light, distance and a moving checkout belt need a real-store benchmark.
- **Shelf-price association needs a benchmark.** Ambiguous labels stay hidden; a package number, deposit or unrelated nearby tag must not become the product price.
- **Rimi/Livin/Livinn snapshots are not market-wide.** Rimi is intentionally limited to seven selected food and drink categories (6,822 complete rows from 7,617 pages); Livin Latvia contributes 6 complete rows; Livinn Lithuania contributes 2,489 edible identities. Its runtime nutrition layer keeps 1,851 conservative within-retailer identities after two duplicate records are removed without relying on invalid codes and two contradictory tables are excluded from eligible Fit counts. Recurring production reuse still requires retailer permission.
- **Open Food Facts coverage is still bounded and community-maintained.** The original 500 records and their aliases are preserved; a separate 596-record regional layer contains only accepted new GTINs. It is not a complete LV/LT/BY market census, and new rows have no inferred translated names. A source record does not prove current store availability or a matching physical recipe.
- **Retailer snapshots age.** Checked-in product and nutrition indexes are reproducible discovery snapshots, not real-time stock or price guarantees.
- **Grounded nutrition can be unavailable.** Identity appears first; exact internet enrichment is background-only, requires a readable pack size or barcode, and its final grounded-search fallback defaults to 12 seconds.
- **The investor URL is public.** Direct entry intentionally has no viewer access challenge. The silent same-site session, origin checks and rate limits reduce bare API abuse but are not authentication; restore an explicit identity or access gate before sharing restricted retailer data broadly.
- **Railway config-as-code needs migration before 1 December 2026.** The current `railway.json`/`railway.toml` deployment still works, but Railway now recommends `.railway/railway.ts` and prints a deprecation warning during deploys.
- **Amplitude Starter limits Funnel charts to two steps.** The saved activation chart measures `app_opened` to `scan_completed`; onboarding, camera-permission, scan-start and feedback events remain available in Live Events and can be explored in separate charts without upgrading.
