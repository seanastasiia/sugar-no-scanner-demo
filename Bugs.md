# Bugs

This file is the running record of scanner defects found and resolved.

## Open

- The current managed QA sandbox rejects all local socket binds, including `127.0.0.1`; the QA-authored Mobile Safari regressions must run in CI or a normal local shell before release.
- Real packaging, glare, low-light and physical checkout-belt accuracy are not validated. The first proof of concept uses curated sample scenes only.
- Shelf-price OCR and spatial association with the correct product label need a physical Latvian store benchmark; ambiguous labels must remain hidden.
- Barbora is the only live retailer source. The prototype can say `Barbora online`, but cannot claim `best price` until multiple comparable retailers, exact pack-size matching and freshness rules are connected.
- The 19,076-entry sitemap index is a discovery snapshot, not a promise that every page is in stock or that packaging and prices have not changed.

## Resolved

- **2026-08-24: final Mobile Safari CI found 4.34:1 contrast on compact tray SKU names and one hydration-time demo-button flake.** The artificial name opacity is removed so text clears the 4.5:1 WCAG AA threshold. Browser setup now waits for network idle, retries the demo trigger once after hydration and gives the chooser the same explicit ten-second cold-start budget as recognition flows.
- **2026-08-24: fiber was a required third rating input even though Latvian retailer data often omits it.** Sugar.no fit now uses only protein and inverse total sugar with equal weight. Fiber remains available in raw source records for compatibility but is absent from the badge, comparison formula and completeness rules. All 40 curated products now have the two required factors; exact Barbora foods receive a fit only when energy, protein and total sugar are source-backed.
- **2026-08-24: expanded multi-product tray cards showed only the brand, so two recognized variants from the same brand were visually and accessibly ambiguous.** Each tray card now names the recognized SKU or variant and exposes a matching selection label while keeping the horizontal shelf comparison compact.
- **2026-08-24: the repeated-package Mobile Safari check depended on the separate uncertain-frame focus retry, obscuring the shelf grouping behavior it was meant to prove.** It now sends four same-SKU facings through two broad shelf-completion frames and verifies one held result, then verifies that `Scan again` replaces it with the next SKU.
- **2026-08-24: first-run partial-fit WebKit checks could exceed the generic five-second assertion window while the upload result and nutrition payload hydrated, then pass immediately on retry.** The acceptance wait now uses the same explicit ten-second recognition budget as the live shelf scenarios, so cold CI startup is not mistaken for a product failure.
- **2026-08-24: an identity-only API payload with `ratingBasis: null` could crash fair-comparison rendering in Mobile Safari.** Fair cohort construction now ignores any product without a rating basis, at least two signals and criterion scores. The product remains identified in the result list, but it cannot enter or break Sugar.no comparison ranking.
- **2026-08-24: the Mobile Safari camera harness could remain at `Waiting for camera permission…` because WebKit never advanced the synthetic video to a playable frame.** The shared camera mock now supplies deterministic video readiness and safe canvas frames, so broad shelf, completion-retry, provider-failure, rate-limit and repeated-pack scenarios exercise the actual automatic capture loop in CI.
- **2026-08-24: saved-photo acceptance could try to populate a hidden file input before the demo chooser finished opening.** The helper now waits for and scopes the file input to the visible demo dialog, removing upload races across partial-rating and price-comparison tests.
- **2026-08-24: older browser checks still expected identity-only products to receive camera markers.** They now encode the product rule: only products with a numeric Sugar.no fit receive an overlay; visual-only identities remain available in the result list without an `i` marker.
- **2026-08-24: Mobile Safari acceptance used page-wide exact text locators for a result string intentionally shown in both the camera status and the bottom sheet.** Assertions now target the live `status` region, so the suite tests the intended product state without failing Playwright strict mode on duplicated explanatory copy.
- **2026-08-24: WebKit reported a hydration mismatch and skipped valid recognition requests because Safari's initial `navigator.onLine` value disagreed with the reachable local server.** The first render is now deterministic, recognition trusts the actual request instead of the unreliable hint, and subsequent online/offline events still update the UI.
- **2026-08-24: real shelf frames had no reproducible API-level benchmark path outside the browser file picker.** `benchmark:recognition` now reads bounded local JPEG/PNG/WebP files in memory, submits them sequentially to the same `/api/recognize` contract, hydrates rating metadata and reports unique identity, exact-recall, rated-coverage, duplicate, latency and `imageStored: false` evidence. - **2026-08-24: live camera cadence exceeded the first public rate-limit default and `429` retried forever.** The default is now 36 requests per 60 seconds versus roughly 29 stable-frame attempts per minute. A `429` pauses the capture loop, reads `Retry-After`, preserves a provisional result and exposes explicit retry/demo actions. Samples remain exempt; unit and browser regressions encode the contract.
- **2026-08-24: provider-unavailable responses did not stop automatic capture.** The camera loop now pauses immediately, preserves a provisional result when present and exposes explicit retry/demo actions instead of repeatedly spending requests.
- **2026-08-24: an uncertain shelf-completion pass erased a valid first product.** A single broad-match result is now held provisionally while the full shelf gets one more pass. If that pass is uncertain, the first detection remains visible and locked with `Scan again`; it is no longer cleared.
